# ADR-002: Automatización de pruebas para la cadena de frío

- **Estado:** Propuesto
- **Semana:** 2 — Streaming y validaciones
- **Fecha:** 2026-10-28

## 1. Contexto

El proyecto RapidGo 360 necesita validar los eventos de la cadena de frío y comprobar las reglas básicas de temperatura, humedad y exposición prolongada fuera de rango.

Para facilitar la detección temprana de errores, se configuró un flujo de integración continua mediante GitHub Actions.

## 2. Decisión

Se decidió utilizar `pytest` para ejecutar pruebas automatizadas de Python y `jsonschema` para validar los eventos contra el contrato JSON definido en `docs/schemas/evento_cadena_frio.schema.json`.

El workflow `.github/workflows/ci.yml` ejecuta las validaciones al realizar cambios mediante `push` y `pull_request`, y permite la ejecución manual.

## 3. Alternativas consideradas

- **Validación manual:** requiere ejecutar y revisar cada caso manualmente.
- **Pruebas automatizadas con pytest:** permiten repetir los casos de prueba y detectar errores de manera consistente.

Se eligió la segunda alternativa para facilitar la validación continua del proyecto.

## 4. Evidencia

En GitHub Actions se verificaron 17 pruebas aprobadas:

- 7 pruebas de validación del contrato JSON.
- 6 pruebas de reglas básicas de temperatura y humedad.
- 4 pruebas de exposición prolongada fuera de rango.

La ejecución terminó correctamente, sin fallos.

## 5. Limitaciones y trabajo pendiente

Las pruebas de reglas de negocio utilizan funciones auxiliares dentro de los archivos de prueba. Todavía no constituyen una integración con Spark Structured Streaming.

Queda pendiente integrar las reglas con el procesamiento de eventos, validar los KPI temporales y comprobar su funcionamiento con datos reales del pipeline.

## 6. Consecuencias

La automatización permite comprobar el contrato y las reglas auxiliares de manera repetible. Los resultados obtenidos sirven como evidencia inicial para continuar con la implementación del procesamiento de eventos.
